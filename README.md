# How Predictable Are CI Build Failures? A Leakage Explicit, Baseline Calibrated Replication on TravisTorrent

Replication package for an anonymized study on leakage-controlled CI build-outcome prediction.

Every number in the paper is computed from the public TravisTorrent 5/3/2016 snapshot by the scripts in this package. No synthetic data is used.

## Evaluation protocol

| Area | Earlier setup | Current study |
| :--- | :--- | :--- |
| Baselines | none beyond a random ranker | previous finished outcome, mean of the last five finished outcomes, logistic regression on history features |
| Lagging of history features | by start order | by completion time: build j enters the history of build i only if finish_j <= start_i |
| Evaluation design | one 70/10/20 cut | six expanding window (rolling origin) folds; the single cut is kept as a robustness check |
| Autoencoder | variance floor 1e-4 made zero variance columns dominate | zero variance features excluded, weights floored at a tenth of the median variance |
| Operating points | 92nd percentile for unsupervised, 0.5 for supervised | matched ten percent alert budget for every scorer; native and rolling thresholds also reported |
| Cost model | full build credited to a true positive, flat two minute false alarm cost, no false negative cost | job minute compute, information loss cost for true positives, false alarm cost swept from two minutes to one build, and a separate build skip scenario with a missed failure cost |
| Inference | independent bootstrap, tallies from raw p values | moving block bootstrap stratified by fold, Holm adjusted tallies, block length sensitivity, intervals on pooled means, sign and Wilcoxon tests across projects |
| Ablation | telemetry (which contained label history) against churn, autoencoder only | history / telemetry / churn / repository groups, every learned detector |
| Leakage list | 16 post execution columns | plus three retrospective comment counts; observation time of every retained column documented |
| Project selection | described as the ten largest | actual rule stated; the four larger projects that the rule skipped are evaluated as a robustness set |
| Label | any non passed job | lenient and strict (failed or errored only) labels, both evaluated |
| Figures | a stale directory shadowed the current figures | single figure directory, every figure regenerated by one script |

## Headline result

Pooled over the ten primary projects and six rolling origin test windows each (mean over windows, then over projects):

| Scorer | Mean AUROC | 95% CI over projects | Projects with AUROC > 0.65 | Mean AUPRC lift | Precision at a 10% alert budget |
| :--- | ---: | ---: | ---: | ---: | ---: |
| Previous finished outcome | 0.627 | [0.596, 0.659] | 3 / 10 | 1.46 | 0.51 |
| Mean of last five finished outcomes | 0.623 | [0.591, 0.657] | 3 / 10 | 1.41 | 0.49 |
| Logistic regression on history | 0.630 | [0.598, 0.663] | 3 / 10 | 1.48 | 0.50 |
| Autoencoder (repaired) | 0.517 | [0.497, 0.535] | 0 / 10 | 1.15 | 0.39 |
| Isolation forest | 0.548 | [0.521, 0.575] | 0 / 10 | 1.25 | 0.40 |
| PCA reconstruction | 0.523 | [0.508, 0.537] | 0 / 10 | 1.12 | 0.37 |
| Random forest | 0.598 | [0.566, 0.631] | 2 / 10 | 1.37 | 0.45 |
| Gradient boosting | 0.577 | [0.549, 0.607] | 1 / 10 | 1.31 | 0.43 |

Mean test-window prevalence is 0.35, so a lift of 1.0 and precision of 0.35 match random ranking. Under paired fold-stratified moving-block bootstrap with Holm correction, no learned detector has a significant win over the last-five rule on AUROC. Random forest has one significant AUPRC win and one loss. Outcome history carries most signal; other feature groups add little. Full tables: `docs/summary.md` and `docs/*.tex`.

## Reproducing the study

```bash
pip install -r requirements.txt

# 1. Fetch the dump (82 MB) and extract fourteen build level project files
python3 scripts/download_data.py --version 2016_snapshot
python3 scripts/extract_projects.py

# 2. Run the benchmark (about 25 minutes on eight cores)
python3 scripts/run_experiment.py --n_boot 2000 --n_jobs 7

# 3. Skip scenario (build selection at a 50 percent skip budget, about 10 minutes)
python3 scripts/skip_scenario.py --skip_budget 0.5 --n_jobs 7

# 4. Aggregate into tables and regenerate figures
python3 scripts/aggregate_results.py
python3 scripts/make_figures.py

# 5. Build the paper
cd paper && tectonic -X compile main.tex

# Tests
python3 -m unittest discover -s tests
```

Seeds are fixed at 42 throughout. Numerical libraries are pinned to one thread inside the runner because the projects are parallelised with joblib.

## Layout

```
data/build_level/             Fourteen build level project files, extraction manifest, project ranking
src/data_loader.py            Ingestion, completion timestamps, rolling origin folds, concurrency statistics
src/feature_pipeline.py       Completion time lagged features, four feature groups, exclusion lists
src/models/                   Autoencoder, isolation forest, PCA, autoregressive rules, random forest, gradient boosting
src/evaluation.py             Metrics, matched and rolling operating points, cost models, block bootstrap, Holm
scripts/extract_projects.py   Streaming extraction with job status counts and job minutes
scripts/run_experiment.py     Benchmark runner (rolling origin, single cut, ablation, strict label, bootstrap)
scripts/skip_scenario.py      Build skip scenario at a configurable skip budget
scripts/check_text.py         Scans sources and the PDF for em dashes, en dashes and invisible characters
scripts/aggregate_results.py  Cross project tables (docs/*.tex, docs/summary.md, results/cross_project_summary.json)
scripts/make_figures.py       Every figure in the paper
results/                      Per project result JSON and score archives
figures/                      Figures
docs/                         Generated LaTeX tables
paper/                        main.tex, acmart.cls, compiled PDF
tests/                        Unit tests
```

## Data

The source is the TravisTorrent 5/3/2016 snapshot, archived on Figshare (https://figshare.com/articles/dataset/TravisTorrent/19314170). The download script verifies the md5 of the file. The dump stores one row per job and built commit pair; `scripts/extract_projects.py` aggregates rows to builds while streaming and records, per build, the job status counts, the summed job minutes, and whether the latency and status columns disagree across the rows of the build.
